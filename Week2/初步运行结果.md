## 测试1：Docker `ContainerWait` — unbuffered channel

对应修复提交 `4d2d2ea`（`errC := make(chan error)` → `make(chan error, 1)`）。

### 第一次跑失败（记录踩坑）

第一版把子协程的请求耗时写成 100ms，比父协程 200ms 超时短，结果父协程在超时前就收到了错误，"提前返回"的场景根本没发生，修复前后表现一样。**教训：复现并发 bug 必须先画时序图确认各事件的先后顺序。**

### 修正后（请求 300ms > 父协程超时 200ms）

```
========== 修复前：errC := make(chan error) 无缓冲 ==========
[buggy][父协程] 超时，直接返回，不再接收 errC
[buggy][子协程] 请求失败，准备发送错误到 errC
[buggy][检查] ✗ 1 秒后子协程仍卡在 errC 发送 → goroutine 泄漏

========== 修复后：errC := make(chan error, 1) 官方修复 ==========
[fixed][父协程] 超时，直接返回，不再接收 errC
[fixed][子协程] 请求失败，准备发送错误到 errC
[fixed][检查] 子协程已正常退出
```

**结论：复现成功。** 一行缓冲区改动，子协程从"永久卡死"变成"正常退出"，和论文 Figure 1 模式、官方 patch 描述完全一致。

## 测试2：Kubernetes `pkg/watch` Mux 死锁

对应修复提交 `435e0b73`。场景：watcher A 正常读，watcher B 放弃读但未移除，随后分发事件 + 尝试 Stop(B)。

这个程序我改了三版：
- 第1版：Stop 在 distribute 之前调用 → B 被提前删掉，死锁没复现出来；
- 第2版：时序对了但 Stop 启动太晚，修复后场景误报"卡住 1 秒"；
- 第3版（最终）：distribute 先启动，50ms 后 Stop 启动，两个动作并发。

### 最终输出（修复后场景）

```
========== 修复后：select + stopped 信号（官方补丁） ==========
[场景] watcher B 已注册但不再读取 result channel（人还没被移除）
[watcher A] 收到: pod-updated
[distribute] watcher "B" 已停止，跳过发送
[检查] distribute 正常完成
[检查] Stop(B) 正常返回
[收尾] 尝试清理并退出……
[收尾] 本场景正常结束
```

### 最终输出（修复前场景，结尾触发运行时全局死锁检测）

```
========== 修复前：持锁 + 裸发送（原始 Bug） ==========
[场景] watcher B 已注册但不再读取 result channel（人还没被移除）
[watcher A] 收到: pod-updated
[检查] ✗ distribute 卡住超过 1 秒 —— 阻塞在 w.result <- ev 上，且 m.lock 未释放
[检查] ✗ Stop(B) 2 秒都没返回 → 死锁确认
[收尾] 尝试清理并退出……
fatal error: all goroutines are asleep - deadlock!

goroutine 1 [sync.Mutex.Lock]:   ← main：收尾清理等锁
goroutine 19 [chan receive]:     ← watcher A 等下一个事件
goroutine 21 [sync.Mutex.Lock]:  ← Stop(B)：等锁
goroutine 20 [chan send]:        ← distribute：卡在 w.result <- ev，且持有锁
exit status 2
```

**结论：复现成功，而且死锁链完整可见。** goroutine 20（chan send，持锁）就是死锁源头，goroutine 21、1 都死在等它释放的锁上。

**一个意外收获：** 程序结尾的 `fatal error: all goroutines are asleep - deadlock!` 是 Go 运行时**内置 deadlock detector** 触发的——这正好实证了论文 Section 8 的两个结论：
1. 内置 detector 只能检测"**所有** goroutine 都卡死"的全局死锁（我们故意让 main 也去等锁才触发它）；
2. 它的处理方式是杀掉整个进程，不是修复。如果只有 distribute 卡住而其他协程还活着，detector 完全无感。
